# SellerMate v0.2

ছোট ব্যবসার জন্য বাংলা/ইংরেজি ম্যানেজমেন্ট প্ল্যাটফর্ম: লগইন, ব্যবসা সেটআপ, CEO ড্যাশবোর্ড, হিসাব, কাস্টমার, বিক্রি, স্টক, AI বোর্ডরুম ও প্রাইভেসি সেন্টার।

Next.js 14 (App Router) · TypeScript · Tailwind · Supabase (Auth + Postgres + Row Level Security).

> **সৎ কথা:** এই কোড আমার এখানে `npm install` / `next build` দিয়ে চালানো যায়নি (ইন্টারনেট বন্ধ ছিল)।
> যা পরীক্ষা হয়েছে: ডেটাবেস স্কিমা (৭১টি পরীক্ষা, আসল PostgreSQL-এ) এবং হিসাবের ইঞ্জিন (২২টি পরীক্ষা)।
> যা পরীক্ষা হয়নি: পুরো অ্যাপের build, পেজগুলো ব্রাউজারে, Supabase-এর আসল Auth, AI কল।
> প্রথম deploy-এ ছোটখাটো error আসতে পারে; Vercel-এর build log দেখে ঠিক করতে হবে।

## চালু করার ধাপ (ফোন থেকেই করা যায়)

### ১. Supabase প্রজেক্ট (বিনামূল্যে)
1. supabase.com-এ সাইন আপ করে **New project** খুলুন (Region: Singapore ভালো)।
2. বাঁ দিকের **SQL Editor** → New query → এই রেপোর `supabase/schema.sql` ফাইলের পুরো লেখা পেস্ট করে **Run**।
   (একবারই চালাবেন। আবার চালালে "already exists" error আসবে।)
3. **Project Settings → API**: তিনটি জিনিস লাগবে: Project URL, `anon` public key, `service_role` key।
   `service_role` key গোপন। কাউকে দেবেন না, চ্যাটেও পাঠাবেন না।
4. **Authentication → URL Configuration**: Site URL-এ আপনার Vercel লিংক দিন (যেমন `https://sellermate.vercel.app`),
   Redirect URLs-এ `https://আপনার-লিংক/auth/callback` যোগ করুন।

### ২. Vercel-এ Environment Variables
Project → Settings → Environment Variables:

| নাম | মান | কখন লাগে |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | সবসময় |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key | সবসময় |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key | শুধু অ্যাকাউন্ট ডিলিট বাটনের জন্য |
| `ANTHROPIC_API_KEY` | Anthropic API key (paid) | শুধু AI বোর্ডরুমের জন্য |
| `AI_MODEL` | (ঐচ্ছিক) মডেলের নাম, ডিফল্ট `claude-sonnet-5-5` | ঐচ্ছিক |

বসানোর পর **Redeploy** করুন (নতুন Environment Variable পুরোনো deploy-এ ঢোকে না)।

### ৩. AI বোর্ডরুম চালু করা
AI শুধু **Business** বা **Growth** প্ল্যানে চলে, আর এখনো বিলিং নেই। তাই প্ল্যান হাতে বদলাতে হয়
(অ্যাপ থেকে কেউ নিজের প্ল্যান বদলাতে পারে না, এটা ইচ্ছাকৃত)। Supabase → SQL Editor-এ:

```sql
update public.workspaces set plan = 'business' where name = 'আপনার ব্যবসার নাম';
```

তারপর অ্যাপে **প্রাইভেসি** → AI চালু করুন → কোন তথ্য দেখা যাবে বাছুন → **AI বোর্ডরুম**-এ প্রশ্ন করুন।

## পরীক্ষা করে দেখার তালিকা (deploy-এর পর)
1. দুটি আলাদা ইমেইল দিয়ে দুটি অ্যাকাউন্ট খুলুন, দুই ব্যবসা সেটআপ করুন।
2. অ্যাকাউন্ট A-তে একটি কাস্টমার, পণ্য, বিক্রি যোগ করুন।
3. অ্যাকাউন্ট B-তে লগইন করে দেখুন A-র কিছুই দেখা যাচ্ছে না। **এটা না মিললে ব্যবহার বন্ধ করে জানান।**
4. পণ্য ২টি স্টকে রেখে ৩টি বিক্রি করতে গেলে "স্টক যথেষ্ট নেই" আসা উচিত।
5. বিক্রি বাতিল করলে স্টক ফিরে আসা ও পাওয়া টাকা "ফেরত" খরচ হিসেবে লেখা উচিত।
6. ড্যাশবোর্ড ও হিসাবের লাভ-ক্ষতি নিজের হাতে মিলিয়ে নিন।

## কী আছে
- **লগইন ও ওয়ার্কস্পেস:** ইমেইল/পাসওয়ার্ড, প্রতিটি ব্যবসার ডেটা আলাদা (Row Level Security), রোল: owner / admin / manager / staff / viewer।
- **অনবোর্ডিং:** ব্যবসার নাম, ধরন, দেশ/মুদ্রা, আকার, পণ্য, কর্মচারী, মাসিক লক্ষ্য, শুরুর ক্যাশ। ব্যবসার ধরন অনুযায়ী মেনু বদলায় (সেবা/ফ্রিল্যান্সারদের স্টক মেনু নেই)।
- **CEO ড্যাশবোর্ড:** আজকের বিক্রি, মাসের বিক্রি, নিট লাভ, ক্যাশ, খরচ, পাওনা, দেনা, লক্ষ্য, ৬ মাসের চার্ট, বিজনেস হেলথ, নজর দেওয়ার তালিকা।
- **হিসাব:** আয়-ব্যয়, বাকি/দেনা, লাভ-ক্ষতি, ক্যাশ ফ্লো, মাসিক সারাংশ। **সব গণনা কোডে ও ডেটাবেসে, AI দিয়ে নয়।**
- **কাস্টমার:** তথ্য, ফলো-আপ, হোয়াটসঅ্যাপ/কল/বাকির রিমাইন্ডার, অর্ডারের ইতিহাস, হারিয়ে যাওয়া কাস্টমার।
- **বিক্রি:** একাধিক পণ্যসহ অর্ডার, ছাড়, ডেলিভারি চার্জ, আংশিক পেমেন্ট, স্ট্যাটাস, বাতিল/ফেরত (স্টক ও টাকা নিজে মেলে)।
- **স্টক:** পণ্য, সরবরাহকারী, মাল কেনা (গড় দামে), স্টক ঠিক করা, কম স্টকের সতর্কতা।
- **AI বোর্ডরুম:** একই মডেলের ৫টি ভূমিকা (CEO, CFO, মার্কেটিং, সেলস, স্ট্র্যাটেজি)। উত্তরে আলাদা করে "তথ্য", "অনুমান", "পরামর্শ"।
- **প্রাইভেসি সেন্টার:** AI চালু/বন্ধ, কোন তথ্য যাবে তা বাছাই, সব অনুমতি প্রত্যাহার, AI-র তথ্য দেখার ইতিহাস, কার্যকলাপের লগ, ডেটা এক্সপোর্ট (JSON), অ্যাকাউন্ট ডিলিট।
- **প্ল্যান সীমা (Free/Starter/Business/Growth):** ডেটাবেসে বাধ্যতামূলক। অ্যাপ থেকে প্ল্যান বদলানো যায় না। বিলিং চালু নেই।
- বাংলা/ইংরেজি, লাইট/ডার্ক, ফোনের জন্য নিচের মেনু, টাকার পাশাপাশি অন্য মুদ্রা।

## AI-কে কী পাঠানো হয়
- শুধু আপনার টিক দেওয়া সারাংশ (যেমন মোট বিক্রি, লাভ, কম স্টকের পণ্যের নাম) আর আপনার প্রশ্ন।
- **ফোন, ঠিকানা, ইমেইল, কাস্টমারের নোট কখনোই নয়।** কাস্টমারের নাম শুধু তখনই (সর্বোচ্চ ৫ জন) যখন আলাদা করে অনুমতি দেওয়া হয়েছে।
- AI সরাসরি ডেটাবেসে ঢুকতে পারে না; অ্যাপ আগে সারাংশ বানিয়ে পাঠায়। প্রতিটি কলের লগ (কখন, কোন ভূমিকা, কোন scope) প্রাইভেসি সেন্টারে দেখা যায়।
- বাইরের AI সেবাদাতা তথ্য কতদিন রাখে তা তাদের নীতির উপর নির্ভর করে। আমরা "শূন্য সংরক্ষণ" প্রতিশ্রুতি দিই না।
- ঘণ্টায় সর্বোচ্চ ২০টি প্রশ্ন।

## যা এই ভার্সনে নেই (ইচ্ছাকৃত বাদ)
- মার্কেটিং অফিস, টিম ম্যানেজমেন্ট (সদস্য আমন্ত্রণ), Decision Simulator, Learning Center, টেমপ্লেট, রিপোর্ট জেনারেটর।
- বিলিং/পেমেন্ট গেটওয়ে (কোনো ভুয়া "পেমেন্ট সফল" নেই)।
- পাসওয়ার্ড রিসেট ("ভুলে গেছি")। Supabase Dashboard থেকে হাতে রিসেট করা যায়।
- ডেমো মোড, v0.1-এর localStorage ডেটা ইমপোর্ট।
- একজন ইউজারের একটি ব্যবসা। রোল আছে, কিন্তু অন্য সদস্য যুক্ত করার পেজ নেই।
- অটো ব্যাকআপ: Supabase-এর নিজস্ব ব্যাকআপ আছে (প্ল্যান অনুযায়ী); অ্যাপ থেকে JSON এক্সপোর্ট নেওয়া যায়।

## জানা সীমাবদ্ধতা
- staff রোল স্ক্রিনে বিক্রির দাম ছাড়া সব দেখে, কিন্তু পণ্যের **কেনা দাম** ডেটাবেসের নিয়মে staff-ও পড়তে পারে (অ্যাপের UI লুকায়)। কড়া গোপনীয়তা দরকার হলে এটা পরে আলাদা টেবিলে সরাতে হবে।
- কাস্টমার তালিকা সর্বশেষ ১০০০, অর্ডার ৩০০, লেনদেন ৩০০ দেখায় (এর পুরোনোগুলো এক্সপোর্টে পাওয়া যায়)।
- ড্যাশবোর্ড প্রতিবার ডেটা লোড করে হিসাব করে; খুব বড় ডেটায় ধীর হতে পারে।

## ডেভেলপারদের জন্য
```bash
npm install
npm run dev          # .env.local-এ উপরের দুটি NEXT_PUBLIC_ ভ্যারিয়েবল লাগবে
npm test             # হিসাবের ইঞ্জিনের ২২টি পরীক্ষা
```
ডেটাবেস পরীক্ষা: `supabase/test/` (একটি আলাদা PostgreSQL-এ `stub_supabase.sql`, `schema.sql`, তারপর `test_schema.sql` চালান; শেষে `ALL CHECKS PASSED` আসতে হবে)।
